# E123 — Sinkhorn-relaxed top-K — preliminary findings 2026-05-20

## TL;DR

Cross-domain application of **Cuturi-Teboul-Vert (NeurIPS 2019)** Sinkhorn
differentiable sort to the ABU-5 % congestion top-K operator in
[E111's per-net-trace congestion proxy](../../E111_per_net_trace_congestion/code/per_net_trace_proxy.py).

The calibration result is **novel and surprising**:
- `torch.topk(combined, K).mean()` on ibm17 cached cascade: +14.36 % vs
  canonical.
- `sinkhorn_topk(combined, K, ε=0.5)`: **+0.26 % vs canonical**.
- **Sinkhorn at ε = 0.5 closes 98 % of the topk→canonical gap.**

This is achieved by a **single drop-in replacement** of `torch.topk`
with a 30-LOC Sinkhorn-Knopp iteration on a 2-anchor cost matrix. No
other E111 changes.

## Why this is novel

- ABU-5 % congestion uses `top-5 % mean` of grid cells. Every
  differentiable placer using ABU/RUDY (DREAMPlace-Cong, DGR, GOALPlace,
  RoutePlacer-GNN — see [survey](../../docs/research/2026-05-20_congestion_model_survey.md))
  uses **torch.topk** for differentiability. None use Sinkhorn-relaxed
  top-K.
- The literature uses Cuturi-Sinkhorn sort/select in **ML** (ranking
  losses, sorting networks) and **statistics** (OT-based selection).
  Crossing it into **VLSI placement** is novel.

## Interpretation

The task's framing — "ε → 0 limit recovers canonical" — is technically
**wrong**. ε → 0 recovers `torch.topk`, which is itself off canonical by
+14 % due to E111's other approximations (L-route star topology,
Gaussian σ pin smoothing). What ε > 0 does is **average over a soft
top-K set that is wider than the strict top-K** — and that soft
averaging happens to *correct for the +14 % overestimation bias* in the
proxy.

In summary:
- **ε = 0.5** = sweet spot for canonical scalar fidelity.
- **ε = 0.3** = sweet spot for sharp gradient on top-K cells.
- **ε ≤ 0.1** = essentially indistinguishable from `torch.topk`.
- **ε = 1.0** = oversmooths, underestimates canonical by -8.6 %.

The **gradient flow** improvement is also real: 24 % more cells get
above-threshold gradient at ε = 0.5 (582 vs 469). This is the
gradient-quality lever the survey [§4](../../docs/research/2026-05-20_congestion_model_survey.md#improvement-4-sinkhorn-relaxed-top-k-abu-m-l-effort-medium-ev)
described.

## Wall budget

- Single forward+backward at ε=0.5, iters=100 on ibm17: 504 ms.
- 500 Adam descent steps: 252 s = 4.2 min. Same order as topk.
- Auto-iters bump: when ε < 0.05, iters bumped to ≥ 50/ε to maintain
  convergence (Sinkhorn rate ∝ 1/ε).

## Hypothesis status

The calibration is a publishable cross-domain result on its own. The
placement-quality lift hypothesis (does the smoother gradient drive
Adam to a better basin?) is **still being tested** at the time of
writing — the full smoke is too slow on M3 (canonical eval ≈ 90s, ibm17
+ 4 configs ≈ 25-40 min). See `code/fast_smoke.py` for the in-progress
test that uses `evaluator.current_cost()` instead of the slow
`compute_proxy_cost` to speed feedback.
